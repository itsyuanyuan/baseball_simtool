# Diamond Lab

Standalone HTML/CSS/JavaScript frontend with a dependency-free Python 3 simulation backend. An original prototype inspired by baseball management games, not a recreation of OOTP's proprietary model.

## Run

Run `python server.py` from this directory, then open http://127.0.0.1:8000. Python 3.10+ is sufficient. Do not open the HTML directly: it needs the local API. The service binds to localhost only.

## League mode

### LAN multiplayer (commissioner + managers)

On the host PC, stop any existing server, then run `python server.py --lan`. It binds port 8000 on all interfaces; other devices on the same trusted network can open `http://HOST-LAN-IP:8000/lan.html`. Keep the host running. If Windows Firewall prompts, allow Python on **Private networks**. No router port forwarding is needed. Guest Wi-Fi/client isolation can prevent devices from reaching each other. This is a trusted-LAN HTTP service, not an internet deployment; invitation keys travel without TLS. Do not expose it to the public internet.

1. On the host, read the commissioner key with `Get-Content data\commissioner.key` (PowerShell). Open `/lan.html`, paste that key, and sign in. Never send that key to managers. It is saved locally and excluded from Git.
2. Use **Create a league or simulate games** to create a season, then return to the LAN clubhouse and open the league. Existing leagues can also receive invitations.
3. Verify the shareable server address uses the host's LAN IP. Click **Invite manager** beside a team and send that private link to its manager. An invite grants control of that one team. **Replace invite** revokes the previous key. Sign-in credentials are kept in sessionStorage for that browser tab; save your invitation if you need to reconnect later.
4. Managers can import career JSON in their own browser's Player Vault, return to/reload the lobby, and assign snapshots before opening day. **Save & mark ready** submits their lineup to the host. After the first regular-season game, membership and abilities lock; managers may still reorder the batting lineup and pitcher rotation. Player IDs keep accumulated stats attached to players when lineups move.
5. The commissioner reloads the saved league to get the latest submissions, then simulates the next game/day. Managed teams must be ready; unassigned ghost teams do not block play. The explicit **simulate using last saved lineups** checkbox overrides readiness. Readiness resets for teams that play. In managed leagues, a batch without override is limited to the next scheduled day. The full-season button stops when a later day needs new ready submissions.
6. Managers see readiness, standings and phase updates every five seconds while the lobby is visible. If the league changes during editing, their unsaved draft stays visible and they must reload before submitting. All writes are serialized and version checked. Only commissioner credentials can call league creation, advancement or invitation endpoints in LAN mode, even if a manager tries calling the API directly.

The shared SQLite database persists on the host; browser Vault contents stay on each device until assigned/submitted. League state, results and rosters are viewable by anyone on the LAN who opens the app; there are no private scouting data or personal accounts. Manager access is through invitation keys, not usernames/passwords. The default `python server.py` remains a single-user localhost mode. For multiplayer always use `--lan`, which enforces administrative authentication. Season exports do not include the commissioner key or hashed manager keys. Back up `data/leagues.sqlite3` and `data/commissioner.key` with the server stopped to preserve access and game data together.

Open `/league.html` to create a custom season with 2–16 teams (even counts), 2–20 games per opponent (even counts), a 2/4/8/16-team playoff field, and best-of-1/3/5/7 series. Each team plays every opponent equally, with balanced home/away games. Rename teams, assign imported Player Vault snapshots, and rearrange the batting order before creating the season. Rosters lock at creation. By default the first three pitchers rotate as starters and the fourth relieves; change rotation size and staff order on the Team page. Players currently recover fully between games; no injuries, roster transactions, fantasy point scoring, or persistent pitcher fatigue.

Simulate the next game, next day, or the rest of the regular season. Season simulation commits batches of at most 20 games and can be stopped between batches. Start playoffs after the regular season completes, then advance games or playoff days through the championship. Standings use win percentage, run differential, runs scored and original team order as tiebreakers. Playoffs reseed every round (highest versus lowest); higher seeds host odd games in shorter series and games 1,2,5,7 in best-of-seven. League games extend beyond twelve innings; a 100-inning safety limit rolls back the batch if no winner emerges. Exhibition games retain their twelve-inning limit.

Leagues, cumulative regular-season/postseason batting stats and full individual game records persist in `data/leagues.sqlite3`. Reopening the page loads your active league. Back up that database with the server stopped for a complete backup; the season JSON export includes rosters, schedule, standings, bracket and batting totals, but omits individual pitch logs and has no restore UI yet. Open a completed game to view batting/pitching box scores and pitch logs. Concurrent tabs use a revision check to prevent duplicate advancement; reopen the saved league after an ambiguous network failure. LAN mode uses commissioner and manager access keys. Existing version 0.2 leagues retain their completed games and adopt version 0.3 for future games.

## Use your Yakyolife players

1. Export a JSON object containing `name` and `pastab`, where each key is the player's age and each value contains that year's abilities. See `example-player.json`. A top-level age dictionary, `state.pastab`, and a single flat player are also accepted.
2. Import it in Player Vault, select an age and source rating scale, and map the numeric source fields to the engine ratings. Nested `ratings` or `abilities` containers are supported. Other custom structures must be flattened first.
3. Save the snapshot, then click a batting or pitching slot. The slot assigns the position. Repeat to build both teams; remaining slots use demo players.
4. Set a seed and park, then Play ball. Export the result JSON to keep a game record.

Saved snapshots persist in browser localStorage. Rosters and results currently last only for the page session. Re-importing can create duplicates. There is no connection to your other PC or automatic modification to retire.json/state.js; the exact upstream save integration needs your source files.

## Rating contract

All engine ratings are 0–100. Higher is better except `error`, where higher means more errors. Missing imported ratings visibly default to 50, or 20 for error. Velocity is a relative quality rating, not raw mph/km/h. The import scale applies to all mapped ratings; normalize mixed-unit saves before importing.

The importer defaults to **Yakyolife 0–80 (clamp to 20–80)**. It applies `round((clamp(raw, 20, 80) - 20) / 60 * 100)`, so raw 0–20 becomes engine 0, raw 50 remains engine 50, and raw 80 or above becomes engine 100. This applies to every mapped rating; missing-field defaults are already in engine units and are not converted again. Existing saved browser snapshots are left unchanged: re-import incorrectly scaled ones from the original save. The bundled `example-player.json` now uses the actual abbreviated source format; select **Yakyolife 0–80**. The API still expects normalized engine ratings; a future SQLite adapter should apply this conversion when reading raw JSON, not alter the original stored career history. SQLite integration is not implemented without the database schema/file. Test conversion with `node --test tests/ratings.test.js`.

`stamina`, `contact`, `power`, `eye`, `velocity`, `movement`, `control`, `range`, `error`, `arm`, `sequencing` are required by the API. Within a game, age is metadata and does not apply a second age penalty; between seasons, the development layer ages and updates current abilities. Pitch sequencing combines count-based pitch choice, a sequencing rating, and a repeated-pitch penalty.

## Model and limits

Each pitch resolves zone location, swing decision, contact, and ball in play. Fatigue lowers pitching quality; the bullpen replaces tired pitchers between batters. Batted balls resolve home runs, fielding errors, hits, outs, and double plays. Runner advancement depends on hit type and the fielder's arm. Lineups use a universal DH and each defensive position once. Games use nine innings, walk-offs, and up to twelve innings; unresolved games are ties.

Version 0.2 calibrates aggregate batting and scoring to the 2025 MLB baseline, with tunable coefficients in `engine.py`. It adds HBP, sacrifice flies, and extra-base advancement. Individual player profiles remain experimental. It omits handedness, pitch repertoires, sacrifice bunts, wild pitches, injuries, position proficiency, earned runs, and tactical substitutions. Fielders are sampled uniformly rather than from a batted-ball trajectory. Productive outs are simplified; non-homer walk-offs stop scoring at the winning run, although official hit-type reduction is not implemented. Pitcher R includes inherited runners charged to their original pitcher. Error tendency is a rating, not a literal percentage. A 30-pitch plate-appearance cap forces a ball in play; an extreme 250-PA half inning returns an error. Pitch counts remain low (about 3.36 pitches/PA); pitch-level distributions have not been calibrated.

## API and validation

### Statistical checks

Run `python checks.py` to reproduce 10,000 average-vs-average validation games and 5,000 fresh-pitcher plate appearances for each of six hitter/pitcher pairings. Open `/checks.html` for the comparison with the 2025 MLB average and the Schwarber-like/Ichiro-like archetypes. `public/checks.json` records results, sample sizes, model hash and coefficients; `public/checks-before.json` preserves version 0.1. Optional `--games` and `--matchups` arguments adjust sample sizes. First-PA experiments deliberately exclude fatigue, bullpen differences and runner context; the full-game baseline retains those effects.

Calibration used up to 4,000 `train-v2-*` seeds through `python calibrate.py --games 4000`. Coefficients were frozen before evaluating 10,000 separate `holdout-v2-*` seeds. The regression test uses a third `regression-v2-*` seed set. The holdout produced .2477 AVG, .3163 OBP, .4062 SLG, 4.416 runs/team-game, 1.194 HR/team-game, 22.10% K and 8.38% BB. Targets are .245/.315/.404, 4.45 runs, 1.160 HR, 22.22% K and 8.41% BB, from the rounded 2025 Baseball-Reference league-average row. This matches selected aggregate metrics, not every MLB statistic or the full distribution of player ability. No deGrom-specific tuning has been done. Seed reproducibility applies within an engine version; v0.2 changes previous game outcomes.

`GET /api/demo` returns two example teams. `POST /api/simulate` accepts `{away, home, seed, park}`; each team has `name`, nine `lineup` players with positions C/1B/2B/3B/SS/LF/CF/RF/DH, and 1–13 `pitchers`. Park is 0.7–1.3. Response includes scores, innings, batting/pitching stats, and pitch logs.

Run `python -m unittest discover -s tests -v`. Seven tests cover deterministic seeds, score/hit/pitch/run accounting, HBP/SF/PA accounting and walk-offs, input validation, contact's effect on strikeouts, and aggregate regression tolerances across 1,000 games. No third-party Python packages required. Fonts optionally load from Google Fonts; system fonts work offline.


## Actual Yakyolife save fields

The importer maps `sta` → stamina, `con` → contact, `pow` → power, `eye` → eye, `vel` → velocity, `brk` → movement, `ctl` → control, `rng` → defensive range, `arm` → arm, and `cat` → pitch sequencing. There is no catching ability. Higher `fld` means better error prevention: normalize it, then invert it for the engine's lower-is-better error tendency (`100 - normalized fld`). This is the default; the importer also retains a manual error-tendency option for other formats.

Pitcher-only, fielder, catcher and two-way snapshots may omit unrelated abilities. Missing engine ratings default to 50, except error tendency defaults to 20, and these defaults are displayed before saving. A catcher without `rng` uses neutral range; `cat` is never used as defensive range. Role detection uses the fields in the selected age snapshot. A combined batting/pitching snapshot is two-way, even if it also contains `cat`.

The catcher's sequencing modifies the current pitcher's sequencing as `clamp(pitcher sequencing + catcher sequencing - 50, 0, 100)`. Thus a source pitcher without `cat` defaults to 50, and the catcher supplies the sequencing quality. This is a simple original model, not a verified Yakyolife formula. Neutral catchers preserve the calibrated all-50 baseline. Existing stored snapshots are not rewritten; re-import from the original JSON to apply corrected mappings. Assign a catcher to the C slot for their sequencing to apply.


## Version 0.3: solo team management, speed and development

**Solo leagues remain supported.** Run `python server.py` (without `--lan`) and open `/league.html`. The same SQLite league, schedule, playoff bracket and history are retained. Solo mode does not require a login and ignores LAN readiness checks. LAN mode remains available using `--lan`.

**Team page:** open `/team.html` from the League page. Solo owners and commissioners can edit any team; LAN managers only their assigned team. Set batting order, rotation size, starting-pitcher order and relief priority. A rotation size of 2 means the first two pitchers alternate starts and the remainder relieve. Multi-day pitcher fatigue is now modeled (see v0.4 below); situational closer logic is not. Before opening day, Player Vault snapshots can replace roster slots; after opening day, existing bench players can replace starters, and ordering and rotation size can change. Completed seasons are read-only until advancing to the next season.

**Actual save:** `{ "S": { "name": "Player", "pastab": { "16": { "con": 30, "spd": 45 }, "27": { "con": 75, "spd": 70 } } }, "Seed": "ignored" }`. `S` is an object. Select the entry age in the importer. `Seed` is ignored; league simulation has its own seed. The selected snapshot supplies **current** ratings (the flat engine fields); **potential** is a separate per-ability dictionary built from the maximum source abilities across all age snapshots, clamped and normalized with the same scale. Error tendency is inverted, so its best potential is the **minimum** engine error rating. No invented upside is assigned where the save has no history for an ability: potential defaults to current. Source traits and career statistics are not yet interpreted as engine modifiers. Potential peaks may come from different ages; they are ceilings, not a real historical single-season snapshot. Existing Vault players must be re-imported to get historical potential. Team details display current/potential on the original 20–80 scale; the API uses 0–100. Missing speed defaults to neutral 50.

**Speed (`spd`):** affects attempts to steal second, success against catcher arm, extra-base advancement, infield-hit probability, triple frequency and avoidance of double plays. SB/CS are included in box scores and seasonal totals. Steal events have `plate_appearance: false` and no pitches, so they do not inflate PA or pitch counts. The first speed model uses simplified between-PA steal attempts, not pitch-level leads/pickoffs or steals of third/home. Its coefficients are experimental. The 10,000-game v0.3 all-average check gives .2476/.3163/.4055, 4.418 runs/team-game, 1.176 HR/team-game, 22.14% K and 8.40% BB. Thus the prior aggregate baseline stays close to its targets; this does not validate real individual speed profiles.

**Next season:** after the championship, click **Advance to next season & develop players**. It archives standings, stats, bracket and rosters, preserves the league ID/configuration/invitations, creates a fresh balanced schedule with unique game IDs, resets seasonal stats and readiness, and ages everyone by one year. Original individual game records stay available and prior-season JSON archives are linked on the League page. Development is a simple original seeded model: under 27, current abilities close 10–22% of their remaining potential gap each offseason; ages 27–31 fluctuate slightly; from 32, abilities decline, with faster decline for speed/range/velocity/stamina. Potential is retained. No automatic retirement, injuries, training program, or playing-time-based progression is implemented. Age is capped at 100. This differs from replaying the original Yakyolife career: its history supplies the ceiling, while new current ratings evolve inside this engine. Legacy players without potential get current ability as their ceiling.


## Version 0.4: 26 players, calendar and fatigue

League teams have 9 starting batters, 4 reserves and 13 pitchers. New teams default to a five-man rotation; existing rotation settings remain intact. Old leagues gain ghost reserves and pitchers automatically without losing existing players or results. This is a fixed roster split; two-way roster exemptions and transactions are not modeled.

Open **Team management** to see condition percentages, order starters and relievers, swap a reserve into a batting slot, and enable/disable automatic batter rest. The first rotation slots are starters, the rest are bullpen priority. A scheduled starter below 70% condition yields to the most rested starter. Relievers below 45% move behind rested bullpen options. Automatic rest replaces batters below 65% with a reserve at least 10 points fresher, preferring matching positions. Position proficiency is not yet modeled. These are pregame replacements, not in-game pinch hitters. Midseason saves cannot edit abilities or restore condition.

**Advance day** advances one calendar day (or completes remaining games on the current date); **Next game** skips to the next game and applies recovery across elapsed days. Schedules include a day off after every six game days. Playoffs include a rest day before each round and travel days after games 2 and 5 of a best-of-seven (after game 2 for shorter series). Dates and condition are persisted in SQLite. Existing regular-season schedules retain their original day numbers; new seasons get the new off days.

Experimental condition formulas use engine 0–100 stamina: batters spend `20 − 0.10 × stamina` per start, plus 4 for catchers; pitchers spend `pitches × (1.05 − 0.004 × stamina) + 5` per appearance. Daily recovery is `8 + 0.08 × stamina` for batters and `14 + 0.12 × stamina` for pitchers, capped at 100. Fatigue lowers current-game batting/defense, pitching quality and pitch limits without changing underlying abilities. Offseason resets condition to 100. These workload rules have not been calibrated to MLB injury or usage data; injuries and automatic retirement remain unimplemented.

Aging/development covers all 26 players. Team management shows each player's offseason changes in 20–80 units, including declining error prevention. Age 32+ declines, with faster physical decline; historical potential stays fixed. No additional age penalty is applied within games.

Postseason IDs now include the season number, preventing duplicate SQLite keys when playing another championship. Already-created second-season brackets are repaired on load/advance. Unexpected POST failures return JSON errors rather than dropping the connection; failed batches roll back atomically. Tests cover two complete postseasons, legacy bracket recovery, daily rest, replacements and stat identity, immutable midseason condition, and aging of all roster groups.


## Version 0.5: career library, development, pitching stats and trades

**LAN workflow:** sign in through the LAN lobby, open **Manage team**, and use **Add a career player**. Upload the original `{S, Seed}` JSON directly on that page. Import stores the entire normalized `pastab` trajectory in the league's shared SQLite state. Pick an entry age once (defaults to the first recorded age); you do not need a new age snapshot every season. Existing browser Vault entries can be shared using the expandable Vault section. Old snapshots without history still work, but must be re-imported from the original file to gain a historical development curve. Source traits and career counting stats are not yet used.

Choose a career from **League player library**, then **Replace** beside a roster slot. Replacements save immediately and are available throughout the regular season, including for LAN managers. Save or discard lineup edits first. A career cannot simultaneously occupy two slots or two teams. Replaced careers remain available in this league with their identity, condition and current age; reacquiring them does not reset their abilities. Released players recover on calendar days and age between seasons. During the postseason, managers can still fill ghost slots, so a late invitation remains useful; replacing an existing career and trading wait until the next regular season. Completed seasons are read-only. Library access is shared; a manager can change only their own roster. The original browser-only exhibition Vault remains available.

**Development replaces v0.3's peak-capped random growth:** for each ability, compute the historical change from the player's current age to next age. Interpolate linearly between recorded ages if years are missing. Apply `base + abs(base) × performance_signal + uniform(-0.25, 0.25)` in engine ability units. Error tendency is inverted during this calculation. Batting signal is `3 × (OBP − .315) × PA/(PA+200)`; pitching signal is `2 × ((K−BB)/BF − .14) × BF/(BF+200)`. Both signals are clamped to ±0.25. Good performance increases growth or softens historical decline. Batting affects contact/power/eye/speed; pitching affects velocity/movement/control. Stamina, defense, arm and sequencing follow history plus the small variation because corresponding seasonal performance measures are not modeled. Performance aggregates regular-season team stints by player identity, including after trades; postseason small samples do not affect development.

Outside recorded history, young players gain 15% of the positive gap to their recorded peak, ages 27–31 have a small baseline decline, and age 32+ declines more, especially physically. Historical peaks stay unchanged and **are not caps**: current abilities may exceed them. The engine's absolute 0–100 range (displayed as 20–80) still applies. Offseason reports show base, performance adjustment and random variation separately. This is an explicit game design formula, not an empirically calibrated player-development forecast.

**Statistics:** League → Season statistics now switches between batting and pitching for regular season and playoffs. New games record runs, doubles, triples, pitcher batters faced, home runs and HBP. Batting includes SLG, OPS, ISO, BABIP, K% and BB%; pitching includes G/GS, IP, BF, workload, RA9, WHIP, K/9, BB/9, K%, BB%, K−BB% and FIP*. FIP* uses a fixed illustrative 3.10 constant, not a fitted season constant. Earned runs are not reconstructed, so RA9 is shown instead of ERA. Pitcher wins/losses/saves and WAR are not implemented. Definitions and sources are linked in the UI: [FanGraphs FIP](https://library.fangraphs.com/pitching/fip/) and [batting statistics](https://library.fangraphs.com/offense/offensive-statistics-list/).

Old current-season pitching totals are reconstructed from stored box scores and play logs. Ambiguous duplicate pitcher names leave derived event rates unavailable; no fabricated identities are assigned to current roster players. Older batting counters that cannot be guaranteed remain “—”; old seasons are not replayed. Stats earned before a trade stay with the original team; the new team gets a separate stint.

**Trades:** on the Team page, choose an imported career to offer, another team, and their requested career. Only genuine imported league careers are eligible; generated ghosts and unidentified legacy roster entries cannot be traded. For a legacy career, import its original save through the library first. One-for-one trades must exchange pitcher for pitcher or position player for position player to preserve the fixed 13/13 split and 26-player roster. A manager accepts/rejects incoming offers or cancels outgoing ones. Manager acceptance completes the trade without a second approval; the solo owner/commissioner can manage teams using the team selector. Player IDs, fatigue, age, history and abilities travel with the player. The receiving slot supplies fielding position. Trade proposals do not reserve players; acceptance revalidates ownership and category. Changed rosters invalidate stale team saves and readiness. Offers expire when a new season starts. There are no salaries, prospects-for-cash, multi-player packages, AI trade valuations, or in-season trade deadline in this first version.

Run `python -m unittest discover -s tests` and `node --test tests/ratings.test.js tests/stats.test.js`. Regression coverage includes LAN authorization and midseason imports, ghost restrictions, receiver-only consent, revoked invites, stale offers, trade identity and stats, history interpolation, performance direction, ability growth above peak, pitching accounting, and legacy stat recovery.
